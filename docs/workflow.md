# 采集、地图回放与可靠回传

会话目录和新版阅读器入口请优先参见 [sessions_and_performance.md](sessions_and_performance.md)。

2026-11-11 更新。控制机主目录为 `~/robot_research/bagtools`。

## 录制

`recording/run.sh` 打开录制控制台。“目录”是机器人保存位置，“回传到”是控制机接收位置；“会话名”只影响会话目录名，可留空。三者均可填写。

会话目录是 `session_<时间戳>[_<标签>]`；标签只保留字母数字汉字和 `.` `_` `-`，界面上会当场显示最终目录名。录完可以在会话列表里改名，录制中不行 —— 规则见 [sessions_and_performance.md](sessions_and_performance.md)。

`record_full.sh` 使用原子文件锁。启动准备阶段也能取消。停止会通知会话和真实 rosbag 录制子进程优雅收尾，最多等待90秒；超时报告错误，保留进程和原文件，不强杀。`auto_record_cam.sh` 对定时停止和信号停止统一检查所有分卷，存在 `.active` 就不报完整成功，并输出 `cam_<stamp>.session.json`。

停止录制不等于关闭硬件数据源。不要在 `.active` 尚未关闭时断电。这里不自动启动车辆或导航。

## 数据回传

控制台里「拉回校验」和「删除机器人上的包」都先弹选包窗口：一行一个包，标出大小和
本地状态（本地无 / 传输中 89% / 本地有 / 已验证 / 尺寸不同）。确认选中项之后才动机器人，
误点不会再把整个目录扫一遍。

`传输中` 是 `.part` 还没收完：可以接着续传，但它不算本地副本，删除模式下置灰不可选。

拉回和删除是两个独立动作。删除对每个包重新核对 SHA-256，本地缺副本或内容不一致
的包留在机器人上并报告出来，不会因为一个包而中止整批。

Linux 控制机：

```bash
cd ~/robot_research/bagtools/recording
bash pull_bags.sh --list
bash pull_bags.sh -p 'cam_20261111_052552_*.bag' -l /data/transbot
# 精确点名（选包窗口用的就是这条）
bash pull_bags.sh --names cam_20261111_052552_0.bag -l /data/transbot
# 只删不传：本地校验一致的才删
bash pull_bags.sh --names cam_20261111_052552_0.bag -l /data/transbot --delete-only
# 选包窗口读的结构化清单
bash pull_bags.sh --list-json
```

用 `bash 脚本名` 而不是 `./脚本名`：脚本从 Windows 同步过来时只有内容没有执行位，
`./pull_bags.sh` 会以 126 退出。`remote_record.sh pull` 内部同理，直接调
`python3 pull_session.py`，不经过这一层。

接收器使用一条SSH连接。文件先写 `.part`，断线后重跑同一条命令即可续传；源文件变更时旧部分副本会保留为 `.stale-*`。校验失败副本保留为 `.failed-*`，再次运行从头重传。目的地已有同名但内容不同的正式文件时拒绝覆盖。每个目的目录同一时间只允许一个接收器。

每个文件核对SHA-256、保留mtime后才改成正式名称。`transfer-manifest.json` 记录本次运行的已验证文件和删除结果（再次运行会更新此清单）。默认同时复制源目录中的JSON、YAML和PGM附属文件，避免遗失会话记录与地图；这些附属文件的实际会话归属以关联清单为准，不能凭文件名猜。`--no-sidecars` 可以禁用。源目录出现 `.bag.active` 时拒绝传输。

`-d` 在整个批次完成、目的副本再次校验和源文件重新核对后才进入删除阶段，不会在传完第一卷时就删第一卷。注意 `-d` 删的是整批清单，**包括那些因为本地已有而被跳过的包**；只想删掉确认过的那几个，用 `--delete-only`。若删除阶段发生I/O或权限错误，错误可能发生在部分删除之后，应根据错误及源目录现状确认，不能假定删除是事务性的。

Windows 可以直接运行仓库的 `recording/pull_session.py`，无需安装ROS、rsync或第三方Python包。例如通过已有SSH隧道：

```powershell
# 终端1，保持运行：Windows → 控制机 → 机器人
ssh -N -L 127.0.0.1:22292:192.168.1.11:22 yahboom@192.168.240.148
# 终端2：主机接收，终端会请求机器人SSH密码
python bagtools/recording/pull_session.py --robot jetson@127.0.0.1 --port 22292 -l E:/Transbot_new_bags
```

也支持 `--jump`，推荐已配置密钥时使用。控制机GUI中的目标路径属于Linux控制机，不能直接填写Windows的E盘路径。

## 默认地图视图

有有效关联地图/轨迹时，查看器默认地图视图；包内已有 `map` TF 时也默认地图坐标累积视图。如果只有里程计，则默认“里程计视图”，明确标识为非地图定位；随时可切回车体系。

源bag没有map轨迹时，在控制机运行：

```bash
cd ~/robot_research/bagtools
./rebuild_map.sh bags/cam_20261111_052552_0.bag     # 单个会话
./build_maps.sh --dry-run                            # 先看清单
./build_maps.sh                                      # 扫 bags/，缺地图的都建一遍
```

`build_maps.sh` 负责发现和跳过：已有栅格、还在录制的会话会在清单里标明原因，剩下的逐个交给 `rebuild_map.sh`。后者按包里有什么决定怎么办：

- 包里有 `/map`（录制时 SLAM 在跑）→ **导出**最后一张占用栅格成 `map_<分卷时间戳>.pgm/.yaml`，不重跑 gmapping（重跑会和包里已有的 map→odom 打架）；
- 没有 `/map` 但有 `/scan` → **离线重建**，私有 master 里 gmapping 回放；
- 两样都没有 → 跳过并说明缺哪一样。

中途失败会清掉自己写了一半的产物，下次还能重试（`rebuild_map.sh` 见到同名产物会拒绝动手）。阅读器两种形式都认：优先 `.map.json` 关联，没有就用包旁边的 `map_*.yaml`。

脚本自动纳入同一会话全部分卷，在独立ROS master（默认127.0.0.1:11329）回放，仅允许scan/odom/tf/tf_static话题，绝不回放cmd_vel。它使用gmapping生成新的地图，不保证与历史地图逐像素一致。已经包含map→odom的会话会被拒绝重建，避免重复发布变换。

生成文件位于首卷旁：

- `*.bag.mapping.pgm` / `.yaml`：便携地图。
- `*.bag.mapping.bag`：离线SLAM的地图与TF，可查询拍摄时刻的地图位姿。
- `*.bag.map.json`：源会话文件名、大小、mtime及地图/TF文件关联。
- `*.bag.mapping.log`：诊断日志。

保留整个源会话和上述附属文件。源文件发生变更或附属文件缺失时，查看器会降级而不误套地图。已有输出不会被重建覆盖。旧 `maps/omap_full.*` 因未找到历史关联轨迹，不自动用于新会话。

雷达原始点只转换一次（包含安装平移和旋转），使用所选雷达消息的header时间查询完整TF链，支持tf_static、反向链和里程计插值。断链/过期显示错误，不把车体系数据冒充地图数据。取图按bag记录时间选择最近帧、限定0.5秒窗口；状态行显示实际header时间差，不能把可视化取帧当成硬件同步证明。

每个查看器的临时图像目录独立；后台加载TF，不阻塞界面；倒放/拖回更早时刻会清除原来累积的扫描。地图背景为完整重建栅格，当前窗口跟随机器人显示局部范围。三合一导出会采用当前地图或里程计视图。

地图/里程计视图里雷达点分两层：已经浏览过的扫描画灰色并留在累积图上，当前这一帧画绿色压在最上层。所以"绿"只代表此刻这一帧，"灰"是扫过的痕迹。灰色是刻意的——历史要退到背景里去，而且中灰是唯一在两种底图上都成立的明度：有栅格地图时底图是白灰，没有时是近黑。只想看当前一帧的话，切到车体系，那里只画当前扫描。

## 质量与语义地图

看板“好/可用/花”仍评价数据流连续性，时间指标依据是bag记录时间。详情新增camera_info、TF、地图和cmd_vel的消息清单。即使清单齐全，仍需要：

1. RGB与深度空间注册、有效深度和正确内参。
2. 相机到底盘的标定外参，以及拍摄时刻的地图位姿。
3. 可靠消息时间戳和跨机器时钟。
4. 识别目标后跨帧去重、合并和处理动态物体。

地图和轨迹可离线补建。相机安装外参仍须实际测量/验证，本次修复没有凭空填写标定值。

## 验证

`python3 -m unittest discover -s tests -v` 包含几何、关联、生命周期和传输的隔离测试；不依赖真实车辆，不会启动车辆。新会话已完成离线重建，并在虚拟显示中验证默认地图模式、15秒跳转和图像显示。Windows接收端使用临时测试数据实际验证过SSH续传和SHA-256校验。
