## 1. 项目一句话

机器人（Transbot 履带车 + 3 自由度机械臂夹马克笔）看见墙上的裂缝，在裂缝处画一笔做标注。

**当前阶段**：一期能力摸底（不求画准，求摸清边界）。机器人离线期间，转做仿真验证。

**一期要回答的三个问题**（来自 04）：
1. 臂+笔能画出什么基本图形（点/短弧/直线）？
2. 重复精度多少（回同一角度，笔尖散布多大）？
3. 安全边界在哪（不堵转、不打相机、不戳翻车）？

### 2.3 臂的能力边界（按实测模型）

- 臂是**平面 2R**：j7/j8 都是俯仰、轴平行 → 笔尖走**平面圆弧**，不是空间球面。
- 够不到直线：直线只能靠底盘带笔走（= 04 的 C 方案）。
- 极限前伸 = **34.0 cm**（实测 `L1+L2 = 10.0+24.0`）。
  → standoff 必须 ≈ **40 cm**，不是 25 cm（见 C8）。旧文里的 32.3cm 是 URDF 值，已作废。
- 正确角口径：`e1=j7−95`、`rel=j8−180`、`e2=e1+rel=j7+j8−275`。
  两节共线看 `j8≈180`；`j7+j8≈275` 只是“第二节水平（e2≈0）”的读数关系，
  不能反推 `rel`。
- **无力反馈**：接触靠弹簧笔套 + 过压 + 视觉差分，不能靠力闭环。

### 2.4 可行 standoff 窗口（2026-10-29 按实测模型重算）

“可行窗口”不是一个固定数：**要看你想画多长**。用 `../arm/line_tool.py`
（实测 L1=10.0、L2=24.0、ARM_X=12.9，留 2cm 躲奇异、笔尖离墙 0.5cm）
重算，`z` 是相对 j7 轴的高度：

| 想画 | 可停车（base_link→墙） | 窗口宽度 |
|---|---|---|
| z=8 一个点 | 31.2 ~ 44.2 cm | 13.0 cm |
| z=8~12（4cm 线） | 31.2 ~ 42.9 cm | 11.8 cm |
| z=5~15（10cm 线） | 31.2 ~ 41.7 cm | 10.5 cm |

→ 正确模型的窗口比旧 `urdf` 档宽得多，因为旧模型把 `j7+j8−275`（第二节
世界角 `e2`）当成了小臂相对角 `rel`，重复计入 j7，算出的姿态整体偏折。
旧文里的 25.7~29.7cm 窗口**已作废**。
→ 数字不要背；改参数后用 `../arm/line_tool.py` 的 `line_range()` /
`draw_points()`，或跑 `python3 scripts/test_kin.py` 现算。

### 2.5 两段式原理（01 的核心矛盾）

Astra 量程 0.6~8 m，臂展 34 cm → 不可能在"能测距"的距离直接画。
只能是：**远处测（0.8~1 m，Astra 有效）→ 盲开过去贴墙画
（base_link 约 40 cm，j7 轴离墙约 27 cm）**。

## 3. 算法总纲

### 3.1 流程

```
1. 远处测   : Astra RGB 找裂缝 → 深度取墙面 Z → 算裂缝位姿
2. 底盘就位 : /scan 摆平行（左右墙距差 < 2cm）→ 开到 standoff ≈ 40cm
3. 逆解     : 给定 (x, z) 求 (j7, j8)，无解/超限位/近奇异直接拒动
4. 摆位     : 小步进给到预碰点（离板 5mm），人工微调确认接触
5. 画线     : 雅可比步进，法向 dx=0 保持，只走竖直 dz，单向不回头
6. 回退     : 抬笔离开墙面
7. 验证     : 退 0.8m 拍两张差分确认画上了（不靠力反馈）
```

### 3.2 核心公式（当前实现位置：`wallmark_kin.py`，项目根目录）

```
e1  = j7 − 95                     连杆1 世界仰角（j7=95 时水平）
rel = j8 − 180                    连杆2 相对连杆1 的转角（j8=180 时共线）
e2  = e1 + rel = j7 + j8 − 275    连杆2 世界仰角

# j7+j8≈275 只是 e2≈0（第二节水平）的读数关系，不是 rel 的定义。
# 当前正确实现：../arm/line_tool.py；wallmark_kin.py 已同步到同一口径。

FK:  x = L1·cos(e1) + L2·cos(e2)
     z = L1·sin(e1) + L2·sin(e2)      （相对 j7 轴心，x 车头方向，z 上）

IK:  2R 标准解，|L2−L1|+1 ≤ D ≤ L1+L2−2（躲折叠/伸直奇异），
     再用 j7∈[0,225]、j8∈[15,240] 过滤

步进: J·[de1,de2] = [0, dz]，det = L1·L2·sin(rel)
      |det| < 30 → 退化为 j8 单动：dj8 = dz / (0.419·cos(e2))
```

## 4. 矛盾点裁决

> 每条给出：**现象 → 涉及文档 → 裁决（谁说了算）→ 处置**

### C1 ★ j7 到底是什么自由度
- **现象**：04 写 "j7 底座 0~225°（**偏航**），j8 升降（俯仰）"；05 写 "j7/j8 两节上下摆动，**均为俯仰**"。
- **裁决**：**05 对，04 错**。j7/j8 都是俯仰（2026-10-21 用户确认，且 04 的写法会推出"球面弧"这种俯仰+俯仰不可能的结论）。
- **连带修正**：04 的 "笔尖走的是球面弧" → 应为 **平面圆弧**；04 的 "B. 偏航扫弧" → **俯仰扫弧**（动作本身没问题，j7 单动确实能画出弧，只是叫法要改）。
- **处置**：已在 04 加勘误块。

### C2 ★ 相机到底是坏了还是没起
- **现象**：README 和 00 写 "相机异常：无 /camera/* 话题"；03 写 "相机没坏，是 WiFi 搬不动，机器人本地 30Hz 正常"。
- **裁决**：**03 对**，README/00 的结论已过期（当时只看到了"话题不在"的表象）。
- **处置**：README 与 00 加过期标注；结论统一为 **视觉必须跑机器人端，VM 只收结果**。

### C3 ★ L1 到底 10 还是 8.285
- **现象**：05 钢卷尺实测 `l1 ≈ 10.0cm`；厂家旧 URDF 实算 `8.285cm`，差 1.72cm。
- **裁决**：**实测 10.0cm 为准**（2026-10-29 用户确认；`transbot_arm_simple` 的模型也是 10.0）。旧 URDF 是厂家模型，但真机是人工安装的，不能用它覆盖实测。
- **影响**：L1 直接进 IK；用 8.285 会让笔尖位置整体偏 1.7cm。
- **处置**：`wallmark_kin.py`、`draw_ready.py`、`../arm/line_tool.py` 和 Gazebo `arm_simple.urdf` 全部用 10.0；URDF 档冻结为 LEGACY。

### C4 ★ 臂座位置 12.9 还是 18.341
- **现象**：04 写 "臂装在 base_link 后上方 xyz=0.129 0 -0.014"，脚本据此设 `ARM_X=12.9`；旧 URDF 反推 j7 轴心在 `x=18.341cm`。
- **裁决**：**实测 12.9cm 为准**（2026-10-29 用户确认）。18.341 是旧 URDF 的几何，不是这台真机的安装位置。
- **影响**：standoff 会差 5.4cm；按 40cm 摆位，笔尖实际到位/不到位差这么多。
- **处置**：控制路径统一用 `ARM_X=12.9`、`ARM_Z=0`（j7 轴离地 8.0cm）；旧 URDF 值只留在 LEGACY 对照里。

### C5 ★ 05 灵敏度表的符号和角度都用错了
- **现象**：表头 "上1cm（j8改变量）" 给的是 **负号**，且把第一节仰角 e1 当成了第二节仰角 e2。
- **裁决**：**j8 增大 = 笔尖升高**，上走 1cm 应为正号；数值要用 `e2` 现算。e2≈0 时正确值是 **+2.39°/cm**，不是 +2.5/+2.8/+3.4/+6.4。
- **危险点**：照旧表手动操作会把笔画反方向，或走过头。
- **处置**：05 已加勘误，旧表标注“已作废，仅存档”。

### C6 ★ 05 表第 4 行也不是共线行
- **现象**：旧文把 (163,113) 的和 276 当成“近似共线”；按正确角口径，它的 `rel = j8−180 = −67°`、`e2 = 1°`，第二节几乎水平，不是共线。
- **裁决**：四行都不是“两节共线”，而是“第二节接近水平”的一组接触位；
  共线条件是 `j8≈180`（rel=0）。若还要求整臂水平，则另有 `j7≈95`、`j7+j8≈275`。
- **处置**：05 用正确 e1/rel/e2 重算；旧表只作原始记录。

### C7 ★ 关节限位的含义
- **现象**：旧文写 j8 15~240°，又写 URDF `arm_joint2` 是 −15~225°，且由旧映射推出“j8 范围随 j7 变”。
- **裁决**：**控制端统一用最新 GUI 的舵机限位** —— j7 `0~225°`、j8 `15~240°`、j9 `60~180°`（2026-10-29 用户确认）。旧 URDF 的 `t1/t2` 换算是历史对照，不再作为控制限位。
- **处置**：`../arm/line_tool.py`、`wallmark_kin.py`、UDP agent、GUI 全部用这一组；`urdf_theta_limits_ok()` 只保留为历史映射自检。

### C8 ★ standoff 25 还是 40
- **现象**：01 流程写 "开到 standoff 25cm"；06 实测说 27cm **真无解**（折叠奇异+超限位），
  当时退到 40~43cm；05 的臂展 L1+L2=34cm 也指向 40cm。
- **裁决**：**base_link→墙 ≈40cm**（01 的 25cm 作废）。按当前实测模型重算的
  完整窗口见 2.4（31.2~44.2cm，取决于要画多长）。
- **处置**：01/06 已标注；脚本默认值按 40。

### C9 ★ 臂展 30 还是 34

- **裁决**：**34cm**。
- **处置**：01 标注。

## 5. 仿真验证结论（历史，2026-10-21）

> **2026-10-29 归档说明**：这一节基于旧 `transbot_gazebo` + 厂家 URDF 模型，
> 其 `demo/` 已移出本仓库（仅保留在作者本地归档中）。
> 旧结论（0.112cm / 0.11cm / 2.985cm）只对旧模型成立，**不再代表当前真机**。

当前能复现的离线验证是 `scripts/test_kin.py`：它用实测几何
（L1=10.0、ARM_X=12.9）和正确角口径，检查 FK/IK 往返、竖直规划、
奇异退化、限位和标定档位。这是现在唯一有效的算法自检。

**结论：算法链路在当前实测模型下仍然自洽；**
真机剩余风险在**机械执行**（舵机回差、笔套、接触确认）和**换笔后的 L2 重标**。
