# 03 关键发现：相机没坏，是 WiFi 搬不动（2026-10-09）

> **本文是 C2 的裁决依据**：README / 00 里"相机异常"的旧结论以本文为准。

## 实测

- 机器人本地（SSH 上直接跑）：`/camera/rgb/image_raw` 30.05Hz，`/camera/depth/image_raw` 30.01Hz，正常。
- VM 侧同样话题：`no new messages`，`camera_info` 时间戳是机器人时钟（2021-08-26，无 RTC/NTP，正常）。
- `lsusb`：`2bc5:050f` + `2bc5:060f`（Orbbec）都在，`astra_camera_node` CPU 48% 在跑。
- `/image`（经 TransbotPatrol 转发的 USB 路）同样无数据。

## 结论

硬件没坏，驱动没死，是 **30Hz RGB+Depth（~200MB/s）把 WiFi 打满**，VM 一帧都收不到。
之前文档说的“相机搬不动”实锤了。

## 对策（影响后续方案）

- 视觉必须跑在机器人端（Jetson），VM 只收结果（bbox/位姿/差分图），和上一阶段 `crack_detector.py` 跑 TensorRT onboard 一个思路。
- VM 侧调试相机只能看降频/压缩：`_throttled` / `compressed` / `theora`，或 `rosrun image_transport republish`。
- 盒子“深度全黑”另有两个叠加原因：太近（<0.6m 盲区全无效=黑）+ 盒子矮（相机俯角看过去，盒子只占画面下半）。
